DeepData vector database has been deployed.

Authentication is mandatory. This release uses exactly one of API_TOKEN or
JWT_SECRET and rejects missing or conflicting credential configuration before
opening persistent state.
The credential is read from existing Secret {{ .Values.auth.existingSecret }},
key {{ .Values.auth.existingSecretKey }} (type {{ .Values.auth.existingSecretType }}).
Secret values are intentionally not accepted through Helm because Helm retains
values in its release record. When rotating the same Secret name and key,
increment auth.secretRevision or restart the Deployment explicitly.
Never set DEEPDATA_INSECURE_DEV_MODE in this deployment; it is only for
credentialless, disposable local development.

{{- if .Values.networkPolicy.enabled }}
Network isolation is enabled: a default-deny NetworkPolicy allows ingress only
on the HTTP ({{ .Values.service.port }}) and gRPC ({{ .Values.service.grpcPort }})
ports and denies all pod egress. It requires a CNI with NetworkPolicy support
(Calico, Cilium, OVN-Kubernetes). On a non-enforcing CNI such as kindnet the
operator must provide equivalent isolation. To disable the chart policy and
manage isolation externally, set networkPolicy.enabled=false.
{{- else }}
networkPolicy.enabled=false: no chart NetworkPolicy is rendered. Apply the
cluster isolation contract for the {{ .Release.Name }}-deepdata pod externally.
{{- end }}

The chart-owned PVC is annotated with helm.sh/resource-policy=keep. Helm
uninstall will orphan it intentionally; back up the whole PVC while DeepData is
stopped and delete retained storage only through a separate reviewed action.

1. Get the application URL:
{{- if eq .Values.service.type "ClusterIP" }}
  kubectl port-forward svc/{{ .Release.Name }}-deepdata \
    {{ .Values.service.port }}:{{ .Values.service.port }} \
    {{ .Values.service.grpcPort }}:{{ .Values.service.grpcPort }}
{{- else if eq .Values.service.type "NodePort" }}
  export NODE_PORT=$(kubectl get svc {{ .Release.Name }}-deepdata -o jsonpath='{.spec.ports[0].nodePort}')
  export NODE_IP=$(kubectl get nodes -o jsonpath='{.items[0].status.addresses[0].address}')
  echo http://$NODE_IP:$NODE_PORT
{{- else if eq .Values.service.type "LoadBalancer" }}
  export SERVICE_IP=$(kubectl get svc {{ .Release.Name }}-deepdata -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
  echo http://$SERVICE_IP:{{ .Values.service.port }}
{{- end }}

2. Check readiness:
  curl --fail http://localhost:{{ .Values.service.port }}/readyz

The gRPC API listens on port {{ .Values.service.grpcPort }}.

3. Use the tenant-aware V3 HTTP API or gRPC API for data operations. Send the
   configured credential as `Authorization: Bearer <token>` (HTTP) or
   `authorization: Bearer <token>` metadata (gRPC). Clients must supply
   vectors; server-managed embedding routes are not part of the RC.
